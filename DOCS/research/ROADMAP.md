## 4. P3：Codex pilot 的最小定义

首轮以内循环为主：选择 P2 已通过的 NS 基线，固定数学算法、输入输出、迭代次数和精度，只尝试数据复用、合法同步收缩和流水调度等实现变化。

此节是后续真实算法pilot。当前FW7先用预定义合成程序与合法调度变体验收通用协调/数值/时序/评分链，不需要先修改NS。

分配一个不改算法的复现候选、三个独立优化候选。所有 worker 使用固定 base 和评估版本；生成并发 2，编译／仿真先串行。控制器记录全部失败与空收益，不要求每轮都产生更优结果。

验收包括：候选文件不交叉污染；退出码和结构化结果一致；损坏／缺失输出不能过门禁；评分来源可追溯；杀掉 worker 后可恢复；冠军在干净工作区重现；预算用尽可停止并保留 incumbent。

pilot 不直接复用带共享 stash 的旧 eval 脚本。旧流程可运行历史实验，但不作为并行新闭环的评估内核。

## 5. P5：BRI 在 CDL-B 下的研究设计

首先检查当前所谓 CDL-B 的模型实现、相关结构、归一化和种子；不能用一个指数相关代理结果代表所有标准 CDL-B 场景。

对齐基准后记录 H 和 A 的条件数、预条件系统谱信息、残差轨迹、SER 与周期。预条件矩阵可能非 Hermitian；需要特征分析时优先使用与 HPD 系统相似的对称形式，避免错误套用普通 Hermitian 求解器。

先重跑历史 B=2 与迭代配置，再在冻结预算内扫描 B、L、松弛／Chebyshev 参数。计入块逆、谱界估计与精度转换。B=Nt 的退化直接法单独标注，不算作低成本 BRI 获胜。

若失败，分辨：实现错误、精度失败、谱界错误、有限迭代预算不足或模型限制。仅当基础路径可信时才研究 deflation／两级预条件，并同时测构建成本与跨右端项摊销。未找到可行点是有效负结果。

## 6. P6：证明框架有效的对照

| 问题 | 对照设计 | 主要观测 |
|---|---|---|
| Agent 是否优于简单搜索 | 固定预算的人工／随机参数搜索 vs Agent | 最佳 verified 周期、可行率、到首个可行解时间 |
| 微架构反馈是否有用 | 仅总周期 vs 单元等待／搬运／依赖反馈 | 收益分布、失败次数、搜索样本效率 |
| 分类错误反馈是否有用 | 原始日志 vs 结构化 hazard 标签 | 修复成功率、重复错误率、修复轮数 |
| 新验证是否有效 | 老 DAG 门禁 vs 新门禁在同一变异集上 | 漏检与误拒，性能作弊是否被拒绝 |
| 外内循环组合是否有效 | 只内循环、只外循环、嵌套搜索 | 相同预算下的质量—周期前沿 |

至少重复多个独立搜索随机种子并报告分布；候选预算、模型用量和墙钟均记录。Claude/Codex 对照需控制任务和评估链，无法控制模型差异时明确局限，不将平台差异全部归因于编排。

## 7. 完成定义

框架 v1 完成意味着：从明确均衡任务自动产生多个候选，运行同程序功能与周期评估，通过独立通信验证，打分并选出可复现候选，形成下一轮任务；中断后可恢复；全部结论可追溯。

仅有 Agent 能生成代码、仿真器能结束、或报告出现 PASS，均不构成闭环完成。
